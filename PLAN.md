## Протокол работы (обязательный)

1. **Сначала этап 0 (git), до любых правок кода.** Каждый пункт плана — отдельный коммит
   с внятным сообщением. Рискованные пункты — в отдельных коммитах, чтобы откат был точечным.
2. **Правило verify-before-rewriting.** Если что-то «не сработало» — сначала открой
   `last-run.log` и проверь, что код вообще дошёл до выполнения (есть ли строка, которую он
   должен был написать). Нет строки — дефект в достижимости (guard, таймаут, ранний выход),
   а не в логике. Дважды в этом проекте переписывали правильный код из-за этого.
3. **Проверять результат, а не код возврата.** Каждый новый шаг обязан сверять фактическое
   состояние (CCD-запрос) после применения. `/SetMonitors` когда-то молча не применял частоту —
   урок остаётся.
4. **Каждый путь, где код сдаётся, пишет `warn:` в журнал.** Молчаливых `return`/`continue`
   не бывает.
5. **Живая проверка после каждого пункта.** Машина с тремя мониторами — и есть тестовый стенд.
   После правки: прогнать реальное переключение (или изолированную сборку формы — для UI),
   убедиться по журналу, что новый код исполнился. Заканчивать сессию всегда в рабочем
   режиме (`Ctrl+Alt+F3` / `work.cmd`), чтобы не оставить стол погашенным.
6. **Языки:** интерфейс и журнал — английский; комментарии в коде, README и этот план — русские.
   Строки журнала с префиксами: `ccd:`, `mode:`, `layout:`, `done:`, `warn:`, `watch:`, `skip:`,
   `settings:`, `tray:`. Новые подсистемы добавляют свои: `windows:`, `auto:`, `audio:`, `hdr:`, `core:`.
7. **Настройки в трее — только через `Get-ActiveSettings` / `Set-ActiveSettings`.**
   `$script:X` внутри блоков с `.GetNewClosure()` разрешается в пустоту — это ловушка PowerShell,
   на ней уже дважды ломались (см. README, раздел «Про интерфейс»).
8. **Тест с модальным окном закрывать из отдельного процесса** — под `MessageBox` таймеры
   WinForms не тикают.

### Чего НЕ делать

- Не возвращать `MultiMonitorTool.exe` в рабочий код (лежит только для ручной сверки).
- Не использовать легаси-запись раскладки (`ChangeDisplaySettingsEx` + `CDS_UPDATEREGISTRY`
  для позиций/primary) — на этой машине она мертва, работает только CCD.
  Для **смены режима** (`Set-DisplayMode`) легаси-вызов работает и остаётся.
- Сторож частоты не трогает разрешение и молчит при полноэкранном приложении — не ослаблять.
- Не переходить на PowerShell 7 (лишняя зависимость, 5.1 предустановлен).
- Ничего не устанавливать в систему: вся философия — «папку можно просто удалить».
- Не кэшировать номера выходов `\\.\DISPLAYx` и Monitor ID — стабильно только название монитора.

## Этап 1 — баг: окно настроек стирает layout и primary

**Место:** `SettingsDialog.ps1`, `Show-SettingsDialog`, блок сохранения (~строка 249).
`$updated = Get-DefaultSettings` — а из формы переносятся только `hotkeys`, `maximizeRefresh`,
`notifications`. Поля `layout` и `primary` уходят на диск дефолтными (`@()` и `''`).
Первый же Save стирает раскладку столов и закреплённый primary: мониторы снова встают
как попало, панель задач ездит.

**Фикс:** после `$updated = Get-DefaultSettings` копировать не представленные в UI поля из
переданных `$Settings`:
```powershell
$updated.layout  = @($Settings.layout | ForEach-Object { [string]$_ })
$updated.primary = [string]$Settings.primary
```
Комментарий рядом: окно правит только то, что в нём есть; остальные поля обязаны проехать насквозь.

**Проверка:** изолированная сборка (`New-SettingsForm` из консоли — рецепт в README) +
регрессионный тест в 4.3: диалог с настройками, где `layout`/`primary` заполнены → Save →
в сохранённом файле поля целы. Живая проверка: открыть Settings из трея, нажать Save,
убедиться что `settings.json` не потерял layout, а переключение всё ещё расставляет мониторы.

## Этап 2 — скорость

Порядок пунктов = порядок исполнения. После каждого — живой прогон и сверка журнала.

### 2.1 Одно чтение настроек на переключение
`Switch-DisplayMode` читает `Get-DisplaySettings` до трёх раз (primary-предпочтение,
fallback primary по layout, сама раскладка). Прочитать один раз в начале в локальную
переменную. Микровыигрыш, но убирает три чтения диска и возможность рассинхрона внутри
одного переключения.

### 2.2 Granular skip: топология
Перед `Set-CcdTopology` сравнить множество активных DevicePath (уже есть в `$monitors`)
с запрошенным. Совпадает → `Write-DisplayLog 'switch: topology already correct'`, топологию
и её ожидание пропустить. Layout, primary и режимы дальше всё равно проверяются (дёшево
после 2.4). Это делает повторное нажатие хоткея почти мгновенным и решает проблему очереди:
нажатия, скопившиеся за время переключения (цикл сообщений трея однопоточный), исполняются
как дешёвые no-op'ы.

### 2.3 Ожидание по условию вместо `Start-Sleep 1200`
**Место:** `DisplayCore.ps1` ~1248 (`Start-Sleep -Milliseconds 1200` + `Wait-ForCcdActive` +
проверка `$stillOn` через полный `Get-DisplayState`).

Заменить всё это одной функцией `Wait-ForTopology`:
```
вход: $WantedPaths, $TimeoutMs = 15000
опрос Get-CcdTargets каждые 200 мс:
  все wanted активны И ни одного лишнего активного → Ok
таймаут → Ok=$false, вернуть списки: кто не поднялся, кто не погас (Label из Get-CcdTargets)
```
Строки журнала сохранить дословно: `warn: not all requested displays came up`,
`warn: refused to turn off: <names>`. Полный `Get-DisplayState` для `$stillOn` больше не нужен —
`Get-CcdTargets` отдаёт и активность, и имена (~10 мс на опрос).

Смысл паузы 1200 был в том, чтобы не прочитать «ещё активен» у гаснущего монитора —
ожидание «лишние погасли» покрывает это по условию, а не по таймеру.

### 2.4 Layout: сравнить, прежде чем применять; ожидание вместо `Start-Sleep 700`
**Место:** `Set-CcdLayout` (`DisplayCore.ps1` ~581–680).
1. После вычисления желаемых позиций сравнить их с текущими `modes[]` (и что якорь-primary
   уже в (0,0)). Всё совпадает → `return $true` без `SetDisplayConfig` (лог не писать или
   писать `layout: already correct` — решить по шуму в журнале). Windows с
   `SDC_SAVE_TO_DATABASE` часто восстанавливает позиции сама — типовой случай станет
   бесплатным и уберёт второе перестроение экранов (моргание + ~1–2 с).
2. Вместо финального `Start-Sleep 700` — опрос (до ~3 с, шаг 200 мс): повторный
   `QueryDisplayConfig` показывает применённые позиции. Таймаут → `warn: layout did not settle`.

### 2.5 Один Add-Type + DLL-кэш
**Сейчас:** три `Add-Type -TypeDefinition` в `DisplayCore.ps1` (NativeDisplay, NativeCcd,
NativeForeground) + один в `Displays.ps1` (HotkeyWindow). В PS 5.1 каждый — это отдельный
запуск csc.exe: CLI-запуски (`status.cmd` и батники) платят ~2 с на каждый вызов, старт трея
на логоне — тоже.

**Сделать:**
1. Слить все четыре класса в один исходник `$nativeSrc` (одна компиляция,
   `-ReferencedAssemblies 'System.Windows.Forms'` — нужна HotkeyWindow, остальным не мешает).
   Комментарий «Отдельным классом, а не полем в NativeDisplay» относился к дописыванию в уже
   скомпилированный тип — совместная компиляция с нуля этому не противоречит.
2. Кэш: `$hash` = первые 8 hex SHA256 от исходника; `$dll = native-$hash.dll` в папке инструмента.
   - guard `('NativeDisplay' -as [type])` — уже загружено, выходим;
   - есть файл → `Add-Type -Path $dll`;
   - нет → `Add-Type -TypeDefinition $nativeSrc -OutputAssembly $dll`, затем `Add-Type -Path $dll`
     (`-OutputAssembly` в PS 5.1 не загружает типы в сессию — проверить и не забыть);
   - любая ошибка кэша → откат на обычный `Add-Type -TypeDefinition` (лог `core: dll cache failed - ...`);
   - старые `native-*.dll` с другим хэшем удалять.
3. В журнал при старте: `core: native types ready in N ms (cache|compiled)`.
4. `native-*.dll` — в `.gitignore` (уже в 0.1).

**Проверка:** `status.cmd` дважды (первый — компиляция, второй — кэш), тайминг в журнале;
трей перезапустить, хоткеи работают.

### 2.6 Длительность в `done:`
`done: ... (4.2 s)` — от `--- start` до сводки. Три строки кода, а даёт постоянный контроль
регрессий скорости прямо в журнале. Оставить навсегда.

### 2.7 (Опционально, риск) Один modeset: позиции внутри топологии
Идея: передавать желаемые source-позиции прямо в `SetDisplayConfig` топологии
(заполнить modes для путей вместо `MODE_IDX_INVALID`), чтобы переключение было одним
перестроением вместо двух. Выигрыш ~1–2 с и меньше морганий.
**Условия:** отдельный коммит; `SDC_VALIDATE` обязателен; любой отказ валидации →
молча откатиться на текущий двухшаговый путь (он остаётся в коде как fallback навсегда).
Делать последним в этапе, только если 2.2–2.4 не дали цели по таймингам. Если цели
достигнуты — пропустить: сложность не окупается.

## Этап 3 — фичи

Каждая — независима, отдельный коммит, выключаемая настройкой. Порядок — по ценности.

### 3.1 Окна помнят свои места (главная фича)
README честно признаёт дыру: «Смена набора мониторов сдвигает окна, и обратно они сами не
раскладываются». Закрыть её.

**Дизайн:**
- Новый файл `WindowLayout.ps1` (dot-source из `DisplayCore.ps1` не надо — подключать из
  `Displays.ps1` и `Set-Display.ps1`; логика вызывается из `Switch-DisplayMode` через
  проверку «функция определена» либо прямыми вызовами из точек входа — решить по месту,
  главное не сломать изоляцию core = «только определения»).
- **Снимок:** перед `Set-CcdTopology` — `EnumWindows`, фильтр: видимые, с заголовком,
  без `WS_EX_TOOLWINDOW`. Для каждого: HWND, PID, путь процесса, `GetWindowPlacement`
  (несёт и min/max, и нормальный прямоугольник).
- **Ключ снимка:** отсортированные DevicePath активных мониторов, join '|' — то есть
  «раскладка столов», а не имя режима.
- **Восстановление:** после `done:`, если для нового ключа есть снимок — для каждого окна:
  окно живо (`IsWindow`) и PID совпадает → `SetWindowPlacement`. Умершие пропускать молча,
  посчитать.
- **Хранение:** `window-state.json` в папке (HWND валидны в рамках logon-сессии и между
  процессами — снимки от CLI и трея общие). При старте трея чистить записи с мёртвыми PID.
- **Журнал:** `windows: saved 12 for <key>`, `windows: restored 9 of 12 (3 gone)`.
- **Настройка:** `restoreWindows` (default `true`), галочка в Settings
  «Remember window positions per display layout».
- **DPI-оговорка:** снимать и восстанавливать в одном и том же процессе с одинаковой
  DPI-осведомлённостью — координаты согласованы. Если делается 4.4 (DPI-awareness),
  сделать её ДО этой фичи, чтобы не мешать системы координат.

**Проверка:** work → раскидать окна → game → work: окна вернулись на свои мониторы и места,
включая развёрнутое окно. Затем то же с закрытым в промежутке окном (не падает, честный счёт в логе).

### 3.2 Авто-игровой режим (opt-in, default off)
- Настройка: `autoGame: { enabled: false, process: "cs2", gameMode: "solo:XG27AQDMGR", backMode: "" }`
  (`backMode` пустой = вернуться в режим, который был до переключения).
- Опрос в уже существующем 15-секундном таймере трея: `Get-Process -Name` (дёшево).
- Логика: процесс появился ∧ текущий режим ≠ gameMode → запомнить текущий ключ → переключить.
  Процесс исчез ∧ переключались мы → вернуть. Ручное переключение во время игры сбрасывает
  «переключались мы» (не воевать с человеком).
- Журнал: `auto: cs2 started -> solo:XG27AQDMGR`, `auto: cs2 exited -> role:work`.
- **Известная гонка:** если игра запущена ДО переключения и успела встать в полный экран,
  смена топологии под ней может дёрнуть окно (игры обычно переезжают на новый primary).
  Задокументировать в README; живой тест с CS2 обязателен. UI для настройки — не делать,
  править руками в settings.json (вписать в README).

### 3.3 Звук следует за режимом (opt-in)
- Настройка: `audio: { "solo:XG27AQDMGR": "<кусок имени устройства>", "role:work": "..." }`
  (пустой словарь = выключено).
- Реализация без внешних exe: COM `IPolicyConfig` (`SetDefaultEndpoint`, CLSID
  870af99c-171d-4f9e-af0d-e63df40c2bc9) + `IMMDeviceEnumerator` для списка устройств —
  всё в тот же общий Add-Type-исходник (2.5). API недокументированный, но стабилен годами;
  если окажется хрупким — запасной вариант NirSoft `svcl.exe` в папке (в духе проекта).
- После успешного переключения: найти устройство по вхождению имени → назначить default
  (eConsole; eCommunications — решить при реализации). Не нашли → `warn: audio device '...' not found`.
- Журнал: `audio: default -> LG ULTRAGEAR (HDMI)`.

### 3.4 HDR переживает переключение
- Перед топологией у каждого wanted-монитора запросить
  `DISPLAYCONFIG_DEVICE_INFO_GET_ADVANCED_COLOR_INFO`; после установки режимов — если HDR был
  включён, а стал выключен → вернуть через `SET_ADVANCED_COLOR_STATE`.
- Настройка не нужна: «вернуть как было» безвредно (если HDR не используется — код спит).
