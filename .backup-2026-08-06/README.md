# Multi-Monitor Tool

Переключатель активных мониторов: значок в области уведомлений, горячие клавиши,
автозагрузка. Интерфейс на английском, эти заметки — для себя.

Внутри — MultiMonitorTool (NirSoft, free, portable) плюс обвязка на PowerShell. В систему
ничего не установлено: папку можно просто удалить, останутся только два ярлыка (Пуск и
автозагрузка).

## Как пользоваться

Приложение поднимается само при входе в Windows. Если закрыл через **Exit** — запусти
заново: `Displays.cmd`, или «Multi-Monitor Tool» в Пуске.

Клик по значку (любой кнопкой) открывает меню:

- **CONNECTED DISPLAYS** — что подключено, в каком режиме, кто основной. Если монитор
  работает ниже своего максимума, рядом будет `(below N Hz)`.
- **SWITCH TO** — режимы. Галочка стоит на том, который соответствует текущему состоянию.
  Недоступный режим показан серым с пометкой `(not connected)`.
- **Settings…** — назначение горячих клавиш и три настройки.
- **Open log**, **Open folder**, **Exit**.

### Горячие клавиши

| Клавиши | Режим |
| --- | --- |
| `Ctrl+Alt+F1` | только LG ULTRAGEAR |
| `Ctrl+Alt+F2` | только LG ULTRAFINE |
| `Ctrl+Alt+F3` | оба LG (Work displays) |
| `Ctrl+Alt+F4` | только ASUS ROG |
| `Ctrl+Alt+F5` | все подключённые |

Меняются в **Settings…**: щёлкни по полю и нажми комбинацию. Нужен хотя бы один
модификатор (Ctrl / Alt / Shift / Win), `Backspace` очищает. Одну комбинацию на два режима
назначить не даст. Если комбинацию уже держит другая программа, приложение скажет об этом
шариком и оставит режим доступным через меню.

Клавиши регистрирует сам процесс (`RegisterHotKey`). Это важно: раньше они висели на
ярлыках в Пуске, а их хоткеи регистрирует Explorer — и только при своём старте, из-за чего
свежесозданные ярлыки не работали до перезапуска Explorer.

Пока ASUS не подключён, `F3` (оба LG) и `F5` (все) делают одно и то же — набор мониторов у
них совпадает. Галочка в меню при этом стоит только у `Work displays`: режим ищется по
первому совпадению, а `all` в списке идёт последним. Не дефект, само пройдёт с третьим
монитором.

### Настройки

| Настройка | Что делает |
| --- | --- |
| Start with Windows | ярлык в `shell:startup` |
| Restore each display to its maximum refresh rate | включено: поднимать частоту до родной |
| Show a notification after switching | шарик с результатом |

Файл — `settings.json`, правится и руками. Привязки для мониторов, которых сейчас нет в
системе, сохраняются: отключённый ASUS не теряет свою клавишу. Такая привязка **видна в
окне настроек** отдельной строкой с пометкой `(not connected)` — например
`Only display AUSAA1D`. Модель монитора взять неоткуда, пока он не подключён, поэтому в
названии стоит короткий Monitor ID. Строка нужна затем, что клавиша занята глобально
(`RegisterHotKey` работает и без монитора), и без неё снять или переназначить её было
нельзя — строки просто не существовало.

Если `settings.json` окажется испорченным, приложение берёт значения по умолчанию, а копию
файла сохраняет как **`settings.json.bad`**. Иначе привязки исчезали безвозвратно: пустой
список клавиш выглядит как первый запуск, и поверх сразу писались значения по умолчанию.

## Из командной строки

    .\Set-Display.ps1 status        что видно сейчас (только чтение)
    .\Set-Display.ps1 modes         ключи режимов и назначенные клавиши
    .\Set-Display.ps1 all           включить все подключённые
    .\Set-Display.ps1 work          все рабочие мониторы (LG)
    .\Set-Display.ps1 ULTRAGEAR     только этот монитор (поиск по названию)
    .\Set-Display.ps1 GSM5CBB       только этот монитор (короткий Monitor ID)

    -PrimaryMatch ULTRAFINE   кого сделать основным
    -KeepMode                 не поднимать частоту до максимума
    -DryRun                   показать команды, ничего не применяя

`status` показывает `Current` и `Best`. Разошлись — монитор работает не в максимальном
режиме. Батники: `all.cmd`, `work.cmd`, `game.cmd`, `status.cmd`.

## Файлы

| Файл | Что это |
| --- | --- |
| `DisplayCore.ps1` | вся логика, только определения. Один источник правды для трея и CLI |
| `Displays.ps1` | приложение: значок, меню, горячие клавиши |
| `SettingsDialog.ps1` | окно настроек. Отдельно, чтобы форму можно было собрать в изоляции |
| `Set-Display.ps1` | командная строка |
| `settings.json` | привязки клавиш и настройки |
| `last-run.log` | журнал: каждый запуск и каждая отданная команда |
| `app.ico` | значок: белый монитор на синей плитке, девять размеров от 16 до 256 px |
| `Make-Icon.ps1` | генератор `app.ico`. Перерисовать: `.\Make-Icon.ps1 -IcoPath .\app.ico -PreviewPath preview.png` |

### Значок

`app.ico` используется и в трее, и на ярлыках — в Пуске, и в автозагрузке. Раньше стояла
иконка `DisplaySwitch.exe`: в Пуске она сливалась с системными.

Настоящий многоразмерный `.ico` (PNG внутри, формат Vista+) `System.Drawing` сохранять не
умеет, поэтому `Make-Icon.ps1` собирает заголовок и каталог руками. Размеры рисуются каждый
отдельно, а не масштабируются из одного: на 16-20 px второй монитор превращался в кашу,
поэтому там остаётся один экран. В трее размер запрашивается у системы
(`SystemInformation.SmallIconSize`) — при масштабе 150% это уже не 16 px.

**Плитка у значка непрозрачная**, и это осознанно: белый глиф без подложки исчезает на
светлой панели задач, а тёмный — на тёмной.

Ярлык в Пуске держит **свою копию** пути к иконке. Если папку инструмента перенести, значок
пропадёт и станет белым листом — путь в ярлыке останется старым. Именно так сломался значок
у WhisperWriter, когда его папка переехала в `Tools\`.

## Как это устроено

### Ничего не прописано жёстко

Режимы строятся из текущего состояния при каждом обращении: у каждого подключённого
монитора появляется свой соло-режим сам. Роли определяются по коду производителя из EDID
(`GSM` = LG → work, `AUS` = ASUS → game). Группа показывается только если в ней хотя бы два
монитора — для одинокого монитора уже есть соло-режим.

Ключ соло-режима — **название монитора** (`solo:LG ULTRAGEAR`). Ни номер выхода, ни один из
Monitor ID кэшировать нельзя, и это проверено дважды:

- **полный** Monitor ID меняется при переносе кабеля в другой порт (у ULTRAFINE
  `GSM5CBB\…\0005` → `\0002`), номера `\\.\DISPLAYx` тоже переставляются;
- **короткий** Monitor ID меняется при переходе на другой **вход того же монитора**. У
  монитора на DisplayPort и на HDMI разные EDID, и код продукта в них разный. После
  перекладки кабелей ULTRAGEAR стал `GSM5BB4` → `GSM5BB3`, а ULTRAFINE `GSM5CBB` →
  `GSM5CBC` — и привязки `Ctrl+Alt+F1/F2` начали указывать в пустоту, режимы «не работали».
  Раньше в этом файле было написано, что короткий ID стабилен. Это неверно: он стабилен для
  пары «монитор + вход».

Название входу не меняется, поэтому ключ теперь по нему. Две одинаковые модели дали бы один
ключ на двоих — тогда к названию добавляется короткий ID. Старые привязки переезжают на
новые ключи сами (`Update-HotkeyKeys` при старте, с записью `settings: moved …` в журнал);
привязка монитора, которого нет в системе, остаётся на месте и видна в окне настроек.

### Порядок и защита

Поднять нужные → одной командой `/SetMonitors` выставить основной и максимальный режим →
погасить остальные. Перед гашением приложение ждёт, пока нужный монитор реально прицепится
к рабочему столу (до 15 с), и если не дождалось — **не гасит ничего**, чтобы не оставить
систему без картинки.

**Одно переключение за раз** (мьютекс `Local\SuperDisplaySwitch`). Без него два быстрых
нажатия запускали два процесса, которые перебивали друг друга — один включал монитор, пока
второй менял ему режим. В журнале это выглядело как случайные отказы. Теперь второе
нажатие отбрасывается с записью `skip:`.

### Меню и кэш состояния

Меню обязано открываться мгновенно, а опрос состояния запускает
`MultiMonitorTool.exe` (~1.5 с). Когда опрос стоял прямо в обработчике `Opening`,
**правый клик по значку не работал вовсе**: Windows успевала решить, что меню не
показалось, и закрывала его. Левый работал только потому, что мы вызываем показ меню
принудительно и он терпит задержку.

Поэтому состояние держится в кэше: он греется при старте, обновляется после каждого
переключения и по системному событию `DisplaySettingsChanged` — то есть и когда монитор
включили или переподключили мимо приложения.

### Частота

Выставляется явно: при включении Windows возвращает монитор в режим из реестра, а он часто
ниже родного — 4K падало до 30 Гц, 2K/144 до 120, ASUS вставал на 59 Гц вместо 240.
Максимум — это **самая высокая частота в родном разрешении**, и разрешение берётся из EDID,
а не у драйвера.

**Почему именно из EDID.** Драйвер сообщал для ULTRAGEAR `Maximum Resolution 3840x2160`:
по HDMI монитор принимает 4K и сам сжимает его в свои 1440p. Правило «самая большая
площадь, потом частота» из-за этого целилось в `3840x2160@60` — применить не удавалось
(в журнале `mode: … failed`), а удалось бы — уронило бы 144 Гц до 60. Родное разрешение
лежит в первом детальном тайминге EDID (preferred timing, offset 54) в реестре, в
`HKLM\SYSTEM\CurrentControlSet\Enum\DISPLAY\<ShortId>\…\Device Parameters\EDID`. Записей у
монитора там несколько — от прошлых подключений; нужная выбирается по значению `Driver`,
совпадающему с `Monitor Key` из `/scomma`.

Четыре неочевидных момента, на которых это ломалось:

1. **`/SetMonitors` не сообщает об ошибках.** Команда `DisplayFrequency=60` уходила, в
   журнале выглядела успешной, а монитор оставался на 30 Гц. Поэтому режим теперь ставится
   через `ChangeDisplaySettingsEx` — он возвращает код, промах виден сразу, и делается
   повторная попытка с проверкой фактического режима.
2. **Режим ставится последним шагом**, после назначения основного монитора и гашения
   остальных. И то, и другое сбрасывает частоту на записанную в реестре, то есть более
   ранняя установка просто затиралась. Сбрасывает её и всё внешнее: например
   `DisplaySwitch /extend` уронил 4K с 60 на 29 Гц на глазах.
3. **Ждать монитор надо с повторами, а не фиксированной паузой.** Сначала после
   `/disable` стояли 900 мс, потом читалась карта выходов — и она ещё отвечала «не
   прицеплен». Установка режима и сводка стояли за проверкой «если прицеплен» и **молча
   пропускались целиком**: в журнале был пустой `done:` и ни одной строки `mode:`, а
   частота оставалась несброшенной. Теперь каждый монитор ожидается отдельно
   (`Get-AttachedOutput`, до 8 с), а не дождавшись — пишется `warn:`.
4. **`CDS_UPDATEREGISTRY` работает не на каждом мониторе.** У ASUS ROG STRIX запись режима
   в реестр отдаёт `failed` для **любой** частоты — даже для той, что уже стоит. Тот же
   режим с `flags = 0` (применить, не запоминать) встаёт мгновенно. Из-за этого монитор
   оставался на 59 Гц вместо 240. Оба LG с записью работают нормально, так что дело в
   мониторе или его записи в реестре, а не в коде.

   Поэтому `Set-DisplayMode` при отказе повторяет вызов без записи в реестр и пишет
   `ok (not saved to registry)`. Частота важнее её сохранения: режим всё равно выставляется
   заново на каждом переключении. Коды `-2`/`-5` (режим невозможен) не повторяются.

   Там же был ещё один тихий дефект: в `Set-BestModeFor` стоял выход из функции по любой
   ошибке, поэтому обещанная в комментарии вторая попытка **не наступала никогда**.

### Скорость

Каждый запуск `MultiMonitorTool.exe` стоит 1-1.5 с, поэтому всё, что можно узнать через
Windows API (имена выходов, кто прицеплен к столу, доступные режимы), узнаётся через API —
бесплатно. Осталось три запуска вместо пяти: ~5 с вместо ~12 с. Нижний предел задаёт сама
Windows — перестроение рабочего стола, тренировка линии DP и синхронизация панели, это 1-2 с
и никаким кодом не убирается.

### Windows не может запомнить раскладку (с 5 августа 2026)

После перекладки кабелей на этой машине **любой** вызов с `CDS_UPDATEREGISTRY` отвечает
`failed` — для всех трёх мониторов. Тот же вызов без записи в реестр проходит мгновенно.
Проверено матрицей: позиция, режим, позиция+режим — с записью всегда отказ, без записи
всегда успех. До перекладки запись работала, в журнале за 4 августа есть `mode: LG
ULTRAFINE -> 3840x2160@60 — ok`.

Отсюда три следствия, и все три — не дефекты кода:

1. **Мониторы не выключаются.** `/disable` требует записи конфигурации. Команда уходит,
   код возврата 0, а монитор остаётся на столе.
2. **Основной монитор не меняется.** Ни `/SetPrimary`, ни `/SetMonitors Primary=1`. А
   выключить основной Windows не даёт — поэтому ASUS не гасится вообще никогда.
3. **Частота не запоминается.** Живёт до следующего сброса.

Против третьего есть сторож (`Restore-BestModes`, ниже). Против первых двух программного
средства нет: приложение может применить режим, но не может заставить систему записать
раскладку.

**Раскладку не меняет вообще ничто.** Проверено четырьмя независимыми способами:

| Способ | Результат |
| --- | --- |
| `MultiMonitorTool /disable`, `/SetPrimary` | код 0, эффекта нет |
| легаси API, реальное изменение позиции с записью | `-1` |
| современный API `SetDisplayConfig` (клон, расширить) | код 0, эффекта нет |
| штатный `DisplaySwitch.exe /internal` (механизм Win+P) | эффекта нет |

Раз не работает и родной переключатель Windows, дело не в приложении и не в
MultiMonitorTool. Обход через `SetDisplayConfig` писать бессмысленно: он отвечает успехом и
ничего не делает.

**Ловушка при проверке.** Матрица флагов, записывающая **те же** значения, что уже стоят,
возвращает 0 по всем вариантам — такую «запись» система принимает всегда. Я на этом
обманулся и решил, что перезагрузка вылечила запись. Проверять надо только реальным
изменением значения.

Что делать со стороны системы: чистая переустановка драйвера NVIDIA (с галочкой «выполнить
чистую установку» или через DDU) — самое вероятное лечение. Дальше: отключить встроенное
видео AMD в диспетчере устройств (оно включено, хотя мониторов на нём нет). В крайнем
случае — удаление ветвей `GraphicsDrivers\Configuration` и `Connectivity` из-под
администратора и перезагрузка (Windows отстроит их заново); эти ключи и читаются только с
правами администратора.

Перезагрузка с тремя подключёнными мониторами **не помогла** — проверено 5 августа.

### Сторож частоты

`Restore-BestModes` вызывается по системному событию `DisplaySettingsChanged`: если
подключённый монитор оказался ниже своего максимального режима, режим ставится заново.
Так ASUS держит 240 Гц, хотя запомнить их система не может. Дребезг гасится (одно изменение
раскладки поднимает событие несколько раз), во время переключения сторож молчит — там режимы
ставятся и так. В журнале это строки `watch:`.

#### Сторож и игры

Сторож дважды ошибался в одну сторону — принимал осознанный выбор приложения за сбой
системы. Оба запрета добавлены 6 августа после того, как из-за них не запускался
Counter-Strike: игра ставила себе режим, сторож возвращал прежний, игра ставила снова.
Экраны моргали, полноэкранный режим сворачивался, а всплывашка «Refresh rate restored»
добивала окно. В журнале это выглядело так:

```
19:12:59  watch: LG ULTRAGEAR dropped to 1440x1080 @ 144 Hz, restoring 2560x1440 @ 144 Hz
19:13:28  watch: LG ULTRAGEAR dropped to 1440x1080 @ 144 Hz, restoring 2560x1440 @ 144 Hz
19:13:46  watch: LG ULTRAGEAR dropped to 1440x1080 @ 144 Hz, restoring 2560x1440 @ 144 Hz
```

**Разрешение сторож не трогает вообще.** Система сбрасывает именно частоту (в журнале
240→144 и 60→29), а разрешение меняют приложения и намеренно: 1440x1080 — это классические
растянутые 4:3 в CS. Если текущее разрешение не равно родному, монитор пропускается со
строкой `watch: … leaving the resolution alone, an app set it` (пишется один раз на
состояние, чтобы не забивать журнал).

**Пока на экране полноэкранное приложение, сторож молчит.** Менять режим под работающим
D3D нельзя — устройство теряется. `Test-FullscreenApp` спрашивает два раза:

| Проверка | Что ловит |
| --- | --- |
| `SHQueryUserNotificationState` (shell32) | состояния 2, 3, 4, 7 — тот же источник, по которому Windows решает, показывать ли всплывашки |
| активное окно закрывает `rcMonitor` целиком | безрамочный полный экран, который первая проверка не видит |

Развёрнутое окно сюда не попадает: оно закрывает `rcWork`, но не панель задач. Рабочий
стол и оболочка (`Progman`, `WorkerW`, `Shell_TrayWnd`) исключены по классу окна.

Проверок именно две, и вторая стоит **после** сбора состояния, а не только на входе:
событие `DisplaySettingsChanged` приходит раньше, чем игра успевает открыть окно, и на
входе полного экрана ещё может не быть. Сбор состояния занимает около секунды — этого
хватает.

Отложенное дело помнится в `$script:RestorePending`, и трей добирает его таймером раз в
15 секунд: выход из безрамочного полного экрана событием `DisplaySettingsChanged` не
сопровождается, ждать его бессмысленно. Строка в журнале — `watch: postponed`.

## Если переключение «не работает»

**Open log** в меню, либо `last-run.log`. Приложение работает без окна, без журнала ошибка
не видна вообще.

Журнал пишется **по-английски**, как и интерфейс: строки из него попадают в сообщения об
ошибках, а смешивать в них два языка незачем. Комментарии в коде остаются русскими.
Записи до 5 августа 2026 — на русском, это просто старая история.

- **`warn: refused to turn off: …`** — команда гашения ушла, а монитор остался на столе.
  См. раздел выше про запись раскладки. Эта проверка появилась не сразу: раньше строка
  `done:` перечисляла **только** мониторы, которые должны остаться включёнными, и отказ
  выглядел в журнале как полный успех.
- **`skip: … the previous switch has not finished yet`** — нажал две комбинации подряд.
  Так и задумано, подожди пару секунд.
- **`ERROR: no display … came up`** — защита не стала гасить остальные. Причина почти
  всегда физическая, см. ниже.
- **В журнале ничего** — приложение не запущено. Проверь значок, запусти `Displays.cmd`.
- **`That display is not connected right now`** — клавиша назначена на монитор, которого
  сейчас нет в системе. Нормально, не поломка.

### Физический слой — самая частая причина

У DisplayPort две особенности, которые выглядят как программные сбои:

**Монитор роняет линк.** Потеряв сигнал, DP-монитор перестаёт быть виден Windows совсем —
неотличимо от выдернутого кабеля. **Проверено на ULTRAGEAR: не помогают ни `/enable`, ни
`ChangeDisplaySettingsEx`, ни `DisplaySwitch /extend`, ни даже кнопка питания монитора.
Помогает только вынуть и вставить кабель.** Программно это не лечится вообще.

То, что нужен именно перевтык, а не питание, указывает на физику разъёма: изношенная
защёлка или плохой контакт на линии Hot Plug Detect. То есть кабель под замену.

Профилактика в меню монитора: **General → `Automatic Standby` → Off** (на части моделей
Deep Sleep Mode) и **`DisplayPort Version` → 1.4**. На ULTRAGEAR это уже выставлено
2026-08-04.

Кабель вставлять до щелчка, с обеих сторон, и не в натяг: короткий кабель за монитором
работает рычагом и выдёргивает себя сам. Для 4K брать только **VESA Certified**.

### Тупики, в которые не надо возвращаться

- **«Это баг Windows 11 24H2»** — час отладки впустую. Симптом «MultiMonitorTool перестал
  включать монитор» давал отходящий кабель.
- **«Деградировала линия DP, поэтому 4K держит 30 Гц»** — тоже неверно. UltraFine
  подключён по HDMI 2.1, и 60 Гц ставились руками без проблем. Настоящая причина —
  `/SetMonitors` молча не применял частоту, см. раздел про частоту выше.
- **Включение дисплея через `ChangeDisplaySettingsEx`** (`CDS_UPDATEREGISTRY | CDS_NORESET`)
  — возвращает `-4` bad flags. На современной Windows подключением дисплеев занимается
  `SetDisplayConfig` (CCD API). Для *смены режима* тот же вызов работает прекрасно.
- **«Фикс частоты не работает»** — фикс был верным, но не запускался: см. пункт 3 в разделе
  про частоту. Прежде чем править логику, проверь по журналу, что она вообще дошла до
  выполнения. Пустой `done:` — признак, что весь хвост функции пропущен.

### Про интерфейс

WinForms на ошибку в построении формы показывает безымянное системное окно без подробностей.
Поэтому окно настроек лежит отдельным файлом и разбито на `New-SettingsForm` (сборка) и
`Show-SettingsDialog` (показ и сохранение) — сборку можно вызвать из консоли и увидеть
настоящее исключение:

    . .\DisplayCore.ps1; . .\SettingsDialog.ps1
    New-SettingsForm -Modes @(Get-DisplayModes @(Get-DisplayState)) -Settings (Get-DisplaySettings)

Так нашлось `Anchor = 'West'`: у `AnchorStyles` нет сторон компаса, только
`None/Top/Bottom/Left/Right`. Вызов из меню теперь обёрнут в try/catch и пишет исключение
в журнал вместе с номером строки.

**Настройки читать и писать только через `Get-ActiveSettings` / `Set-ActiveSettings`.**
Обработчики событий создаются через `.GetNewClosure()` внутри других блоков, и обращение
`$script:Settings` внутри них разрешается **не** в переменную скрипта: окно настроек
получало `$null` и падало на `.Contains()`, а меню молча не показывало комбинации клавиш.
Функция исполняется в области скрипта независимо от того, откуда её вызвали.

Правило шире, чем про настройки, и проверено опытом:

| Что внутри обработчика | `$script:X` виден? |
| --- | --- |
| обычный блок `{ … }` | да |
| блок с `.GetNewClosure()` | **нет**, приходит пустота |
| вызов функции из любого блока | да |

Отсюда два приёма: логику держать в функциях, а простые значения (например имя
приложения для заголовка окна с ошибкой) складывать в локальную переменную **перед**
созданием замыкания — локальные оно как раз захватывает.

Окно проверяется без участия человека: таймер закрывает уже показанную форму нужной
кнопкой. Прогнаны случаи: обычный вызов, `$Settings = $null`, настройки без `hotkeys`,
закрытие через Save (привязки отсутствующих мониторов сохраняются), очистка клавиши в
`(none)` и дубль одной комбинации на два режима.

**Под модальным `MessageBox` таймеры WinForms не тикают.** Тест, который закрывает
диалоги своим таймером, на `MessageBox` вешается наглухо — так и вышло, тест провисел две
минуты. Закрывать такие окна надо из **отдельного процесса**. И не верить его отчёту без
проверки: мой закрывальщик на `FindWindow('#32770')` рапортовал «окна не было» там, где оно
точно было. Надёжнее судить по факту: если вызов не вернулся — окно показано.

## Позиции окон и раскладка

Смена набора активных мониторов сдвигает окна, и обратно они сами не раскладываются — это
ограничение Windows, не тулзы.

Раскладку самих мониторов (позиции, разрешения, кто основной) можно снять и вернуть:

    save-layout.cmd      снять снимок в profiles\all-three.cfg
    restore-layout.cmd   вернуть его

Режимы этим снимком не пользуются, он нужен только чтобы вернуть позиции, если раскладку
перекосило.

## Топология (на 2026-08-04)

| Монитор | Разрешение | Куда подключён |
| --- | --- | --- |
| LG ULTRAGEAR | 2560×1440@144 | RTX 4080 SUPER |
| LG ULTRAFINE | 3840×2160@60 | RTX 4080 SUPER |
| ASUS ROG STRIX XG27AQDMGR | 2560×1440 | не подключён |

У карты 3× DP 1.4a + 1× HDMI 2.1 и **нет USB-C**. Поэтому ULTRAFINE не мог остаться на
кабеле USB-C→материнка: там видео идёт по DP Alt Mode от встроенной графики процессора, в
списке светился `AMD Radeon Graphics`, кадры копировались между GPU через PCIe и курсор на
этом экране дёргался.

Если понадобится подключить USB-C-монитор к карте — нужен направленный кабель
**DisplayPort → USB-C** («DP source to USB-C monitor», напр. Club3D CAC-1557). По нему идёт
только видео: USB-хаб монитора отвалится, для него нужен отдельный USB-кабель в
upstream-порт монитора.
